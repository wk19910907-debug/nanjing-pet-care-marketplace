# 微信小程序构建与履约验收

## 当前边界

原生宠主预约支持首次添加宠物和上门地址：必填宠物名字、开放区域及详细门牌；注意事项折叠为选填。日期与时间使用原生选择器，按北京时间组合。已有资料保存后直接选择，不需要切回网站。

原生服务人员页已接入后端任务、到场确认、图片上传与服务报告。照片先读取真实文件字节，计算摘要，上传成功后登记到订单；页面照片数量和订单状态重新从后台读取。取消选图不计数，上传失败不显示成功，附件登记结果不明时可在当前页面重试。

这不是已经发布的微信小程序。GitHub Pages 是网站静态体验版，不提供共享订单后端，也不能作为小程序 API 地址。自动化测试和构建通过不等于微信开发者工具或真机验收通过。

## 构建与导入

在仓库根目录使用 Node 22、pnpm 10：

```powershell
pnpm install --frozen-lockfile
pnpm --filter @pet/miniprogram build
```

微信开发者工具导入 `apps/miniprogram`。项目配置的代码根目录为 `dist/`；构建产物被 Git 忽略。每次改动源码后重新构建。构建器仅清理上次清单记录的旧产物，保留其他文件。

默认 `touristappid`、关闭域名校验仅用于本地开发，不应作为发布配置。开发者工具的本地扩展配置需要提供 `developmentApiBaseUrl`，例如 `http://127.0.0.1:51800`。`apiBaseUrl` 应指向独立部署的 HTTPS API；未配置时使用不可用占位域名，不会误连线上服务。不要把密钥、令牌或个人账号配置提交进仓库。

## 本地联调前提

- API 必须已启动并通过 `/health/ready`。本机回环地址只能用于开发者工具本机请求，不能作为手机真机地址。
- 开发模式通过仅回环可用的本地会话接口登录；服务人员入口请求 PROVIDER 身份，会话仅保存在内存。正式环境使用微信登录，不开放本地身份切换。
- 测试账号需要在后台完成昵称、服务人员入驻及审核，且拥有已派发任务；本次页面不代替后台审核或入驻。没有任务时显示空列表。
- 当前本地账号尚未完成昵称时，预约页和任务页会展示单字段昵称表单；保存后重新读取后台会话再进入业务。失败保留输入，昵称不能包含联系方式。不再要求切回网站填写昵称；服务人员申请及审核仍需现有网站/后台流程。
- 页面先检查后台会话，只有明确401才尝试一次重新登录；网络错误不会反复登录。正式环境的身份由后端决定，点击服务人员入口不会把宠主提升为服务人员。开发环境不发送缓存的正式 Bearer 凭证。
- 小程序昵称保存使用 POST `/api/v1/pilot/me`；更新小程序时必须同时更新并重启 API，旧 API 没有此 POST 路由。网站原 PATCH 保存接口保留；两个入口复用同一鉴权与昵称校验。
- 只有后台状态为待服务时能到场确认，服务中能上传与提交。接单仍通过现有邀请接口；订单最终确认由宠主或已有后台流程处理。

## 验收路径

### 宠主首次预约

1. 新宠主登录并填写昵称，进入喂猫或遛狗预约；没有资料时显示新增表单。
2. 填宠物名字并保存，填写开放区域和门牌并保存。不要求手机号、微信号、门锁密码或手工坐标。
3. 选择尚未到来的日期与时间，查看报价，再提交订单。修改服务、宠物、地址或时间后必须重新报价。
4. 保存/提交期间不能重复点击或修改输入。网络结果不明时，留在当前页点击“重试确认”，应复用原请求，不增加重复资料或订单；随后出现登录、校验或限流失败也不会解除这次未确认请求的冻结，只有成功结果才会解除。首次提交明确被拒绝时可修改后重新尝试；服务或区域临时关闭会解除首次订单尝试以便重新选择并报价。此保证限于同一页面会话；关闭页面不保存门牌草稿或请求键，重开应先查看后台已保存资料和订单。
5. 同一区多处地址显示具体门牌以便区分；后台与数据库核对只有本人资料。成功提交仅表示订单已创建，当前人工收款模式下订单仍是待支付，不能当成已收款/已派单。

### 服务人员履约

1. 后台给已审核服务人员派发测试订单；首页进入“服务人员 · 我的任务”。
2. 读取任务或接单，进入服务详情；重新打开后应保留后台状态与照片数量。
3. 确认宠物状态后到场签到；服务时间由后台生成。
4. 相册或相机选择 JPEG、PNG、WebP 图片（不超过 20 MiB）。取消、断网、上传或登记失败均不得增加已上传数量；恢复网络后重试。
5. 喂猫勾选宠物数量、补充食物、更换饮水、清理猫砂；遛狗勾选牵引确认并填写实际分钟数。完成离场确认后提交报告。
6. 后台核对证据、服务报告与待确认状态；未满足条件时不能提交。可在另一客户端验证共享数据，而不是只看小程序本地显示。

## 上线前仍需完成

后端已实现 `/api/v1/auth/wechat/session`：服务器交换微信临时 code，建立宠主身份并签发与现有业务兼容的 Bearer 会话。默认关闭，不会回退到演示账号。配置与验证步骤见[微信登录运维说明](wechat-login.md)。代码和受控自动化测试不代表真实微信账号已验收。

仍需真实 AppID/AppSecret、公开 HTTPS 后端、合法请求域名和对象存储域名配置；真机登录、选图、二进制 PUT、错误恢复与服务闭环验收；生产数据库、备份、权限、支付方式和运营审核。新微信账号默认是宠主，不会自动关联网站本地/邀请码账号；服务人员入驻、跨端账号绑定和受审核的身份转换仍需衔接。当前不宣称已可正式接单运营。

## 资料接口升级

更新本次小程序前，须先备份数据库、执行 `pnpm exec prisma migrate deploy` 与 `pnpm exec prisma generate` 并重启后端。新迁移为宠物与服务地址增加可空 `clientRequestId` 及按 owner 隔离的唯一索引，不删除或重写既有资料。原网站不带该字段的请求仍兼容。

新小程序依赖 GET/POST 地址接口的本人可见 `detail` 字段，不能与旧后端混用。列表禁止缓存，门牌加密存储，门禁指令不进入列表。资料幂等键限定1–100位ASCII字母、数字、下划线、横线；同键不同内容返回409，不覆盖已有记录。

目前按南京开放区的中心点校验服务范围，不是客户GPS定位、路线计算或真实里程计费。后续接地图能力需单独实现与验收。

## 本次自动化覆盖

小程序测试覆盖上传字节与摘要、鉴权隔离、本地会话 Cookie、后台全部订单状态、失败重试、重复点击、昵称门槛、会话恢复、实际 Page 事件、WXML 条件绑定和全部 8 个入口的独立构建加载。构建加载测试运行于无 Node/浏览器 URL 全局的隔离 VM，不能替代微信运行时测试。

首次预约另有原生 API 客户端连接真实应用路由及临时 PostgreSQL 的集成测试，覆盖空资料、保存与重试、喂猫/遛狗服务报价和订单重放。微信身份交换使用受控响应，不代表真实微信登录或实际收款。
