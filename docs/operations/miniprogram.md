# 微信小程序构建与履约验收

## 当前边界

原生服务人员页已接入后端任务、到场确认、图片上传与服务报告。照片先读取真实文件字节，计算摘要，上传成功后登记到订单；页面照片数量和订单状态重新从后台读取。取消选图不计数，上传失败不显示成功，附件登记结果不明时可在当前页面重试。

这不是已经发布的微信小程序。GitHub Pages 是网站静态体验版，不提供共享订单后端，也不能作为小程序 API 地址。自动化测试和构建通过不等于微信开发者工具或真机验收通过。

## 构建与导入

在仓库根目录使用 Node 22、pnpm 10：

```powershell
pnpm install --frozen-lockfile
pnpm --filter @pet/miniprogram build
```

微信开发者工具导入 `apps/miniprogram`。项目配置的代码根目录为 `dist/`；构建产物被 Git 忽略。每次改动源码后重新构建。构建器仅清理上次清单记录的旧产物，保留其他文件。

默认 `touristappid`、关闭域名校验仅用于本地开发，不应作为发布配置。开发者工具的本地扩展配置需要提供 `developmentApiBaseUrl`，例如 `http://127.0.0.1:51800`。`apiBaseUrl` 应指向独立部署的 HTTPS API；未配置时使用不可用占位域名，不会误连线上服务。不要把密钥、令牌或个人账号配置提交进仓库。

## 本地联调前提

- API 必须已启动并通过 `/health/ready`。本机回环地址只能用于开发者工具本机请求，不能作为手机真机地址。
- 开发模式通过仅回环可用的本地会话接口登录；服务人员入口请求 PROVIDER 身份，会话仅保存在内存。正式环境使用微信登录，不开放本地身份切换。
- 测试账号需要在后台完成昵称、服务人员入驻及审核，且拥有已派发任务；本次页面不代替后台审核或入驻。没有任务时显示空列表。
- 当前本地账号尚未完成昵称时，后台会拒绝任务读取；先在本地网站的对应身份完成昵称即可。不要把这种拒绝当成小程序已经完成正式注册流程。
- 只有后台状态为待服务时能到场确认，服务中能上传与提交。接单仍通过现有邀请接口；订单最终确认由宠主或已有后台流程处理。

## 验收路径

1. 后台给已审核服务人员派发测试订单；首页进入“服务人员 · 我的任务”。
2. 读取任务或接单，进入服务详情；重新打开后应保留后台状态与照片数量。
3. 确认宠物状态后到场签到；服务时间由后台生成。
4. 相册或相机选择 JPEG、PNG、WebP 图片（不超过 20 MiB）。取消、断网、上传或登记失败均不得增加已上传数量；恢复网络后重试。
5. 喂猫勾选宠物数量、补充食物、更换饮水、清理猫砂；遛狗勾选牵引确认并填写实际分钟数。完成离场确认后提交报告。
6. 后台核对证据、服务报告与待确认状态；未满足条件时不能提交。可在另一客户端验证共享数据，而不是只看小程序本地显示。

## 上线前仍需完成

真实 AppID、微信登录配置与账号入驻流程；公开 HTTPS 后端、合法请求域名和对象存储域名配置；真机的选图、二进制 PUT、错误恢复与服务闭环验收；生产数据库、备份、权限、支付方式和运营审核。当前不宣称已可正式接单运营。

## 本次自动化覆盖

小程序 68 项测试覆盖上传字节与摘要、鉴权隔离、本地会话 Cookie、后台全部订单状态、失败重试、重复点击、实际 Page 事件和全部 8 个入口的独立构建加载。构建加载测试运行于无 Node/浏览器 URL 全局的隔离 VM，不能替代微信运行时测试。
