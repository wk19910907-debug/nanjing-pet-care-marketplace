# 南京上门喂猫与遛狗试点运行手册

## 上线门槛

- 仅开放一个经运营确认的高密度服务圈；价格、半径、佣金和取消费经负责人签字确认。
- 主体、隐私政策、宠主协议、服务者协议、保险和责任边界经专业法律与保险顾问审阅。
- 微信商户号、API v3 密钥、商户私钥、平台证书、回调域名、微信小程序 App ID 和订阅消息模板全部完成生产验证。
- 对象存储启用服务端加密、私有桶、短时签名 URL、生命周期策略和访问日志。
- 数据库开启加密备份、时间点恢复和至少一次实际恢复演练。

## 密钥与数据

- 字段加密密钥按版本配置；轮换时先增加新版本、让新写入使用新版本，再后台重加密旧记录，确认后才停用旧密钥。
- 支付证书、OAuth 凭据、数据库口令和对象存储密钥只存放在秘密管理系统，不进入仓库或日志。
- 服务证据默认保留 180 天；投诉中的证据冻结删除直至结案后再按政策清理。任何延长须有明确合法依据。
- 每日数据库备份，至少每月恢复演练；备份失败和恢复点落后必须告警。

## 服务者审核

审核实名、联系方式、经验材料、服务区域、紧急联系人与协议签署状态。审核员和调度员职责分离；拒绝或暂停必须记录原因。试点期间每位服务者默认同时只执行一单。

## 订单运行

1. 付款成功才派单，每批三人、五分钟，两轮后进入人工队列。
2. 调度列表只显示片区和近似位置，不显示门牌、门锁、宠主电话或敏感宠物备注。
3. 人工指派前确认服务者已审核、可用、无冲突且在半径内；操作进入不可变审计记录。
4. 只有最终服务者在服务窗口内可查看必要入户信息。
5. 未签到、媒体上传失败、宠物异常或无法入户立即进入人工处理，不要求兼职人员作医疗判断。

## 投诉升级与急停

- 客服先冻结结算、保存证据和双方陈述；涉及伤害、失踪、入户安全或疑似违法时立即升级负责人并按协议联系适格机构。
- 可按服务圈、服务类型或全平台暂停新下单；已付款订单必须逐单联系，不得静默取消。
- 支付回调异常、数据库不可写、字段解密失败或证据存储不可用时系统失败关闭，停止新交易。
- 回滚使用上一已验证应用版本；数据库迁移只向前修复，不做破坏性自动回滚。回滚后复核支付回调、任务队列和审计完整性。

## 十单内部试点验收

- 使用内部授权参与者完成至少十单：喂猫五单、遛狗五单。
- 至少覆盖：首轮无人接、第二轮接单、人工派单、迟到、无法入户、上传重试、宠主取消、部分退款、全额退款和自动确认。
- 每单复核付款、派单、敏感地址访问、签到、清单、媒体、报告、确认/争议、退款/结算和审计链。
- 记录首次接单时间、派单成功率、完成率、准时率、投诉率、退款率、客服分钟、佣金和服务者收入，口径使用运营台所列分子、分母、时区和窗口。
- 十单全部完成复盘且无未解释资金差额、越权读取或缺失证据后，才能讨论扩大服务圈。
