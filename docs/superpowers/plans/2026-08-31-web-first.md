# Web-first customer experience

User direction: prioritize website frontend; keep booking simple and ship without repeated choices. Existing warm cream/coral direction is retained. This is the approved scope derived from that standing instruction, not a new backend or mini-program project.

## Design

Compact homepage with two recognizable pet service cards, softer code-native pet icons, visible service prices and direct booking. Secondary pricing controls are collapsed. Put the customer booking workspace before lengthy trust/process explanations. Mobile quick navigation exposes home, booking and orders. Booking remains three steps; successful demo submission displays an explicit demo receipt instead of silently resetting the form. Existing real pilot authentication and data boundaries are retained.

## Global Constraints

- Website frontend only; no API, database, payment, mini-program or authentication changes.
- Preserve platform matching (not owner-selected sitters), configured service availability and prices, and existing operator/provider actions.
- Clearly disclose that the public GitHub Pages experience stores demo orders in the current browser and does not create real orders or charges.
- No invented reviews, counts, guarantees, availability or fake customer-support contacts.
- Mobile 390px and desktop 1280px must have no horizontal overflow; controls have visible focus, labels and comfortable touch targets; respect reduced motion and safe areas.
- Do not add more required booking fields. Preserve entered data on failure.
- Use existing React/CSS patterns and editable decorative vector icons; no new dependency or copied third-party artwork.
