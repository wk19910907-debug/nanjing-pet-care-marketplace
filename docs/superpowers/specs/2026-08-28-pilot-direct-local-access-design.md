# 本地试运营免邀请码设计

## 目标

本地南京试运营不再要求用户输入邀请码。未登录用户直接选择“宠主”“服务人员”或“平台管理员”，服务端创建安全 Cookie 会话并进入现有昵称与工作区流程。

## 范围与边界

- 免邀请码入口只在 `NODE_ENV=development` 或 `NODE_ENV=test` 时注册。
- `NODE_ENV=production` 不注册免邀请码接口；现有生产配置校验、Secure Cookie、Origin 防护和失败关闭逻辑保持不变。
- 服务默认继续绑定 `127.0.0.1`。免邀请码接口还必须校验请求来自 IPv4/IPv6 loopback，避免误把开发服务绑定到局域网后暴露管理员入口。
- 页面删除邀请码输入框、邀请码管理面板和“邀请制”文案。
- 邀请表、邀请兑换服务、管理员邀请接口和旧迁移暂时保留，仅用于已有数据兼容与安全回归，不再作为用户操作入口。
- 不新增手机号、微信号、真实姓名、密码、支付或联系方式字段。

## 服务端设计

新增 `POST /api/v1/pilot/local-sessions`，请求体仅允许：

```json
{ "role": "OWNER" }
```

`role` 只能是 `OWNER`、`PROVIDER` 或 `ADMIN`。接口只在非生产环境注册，并拒绝非 loopback 请求。

`PilotSessionService.createLocalSession(role)` 为每个角色复用一个稳定的本地账号。账号使用固定命名空间经过 SHA-256 得到的内部 `phoneHash` 作为唯一标记，不包含手机号，也不作为认证凭据。创建或找到账号后，服务端生成随机会话令牌，只把哈希写入 PostgreSQL，并通过现有 HttpOnly、SameSite Cookie 返回会话。

并发进入同一角色时使用数据库唯一约束和 Serializable 事务，确保只产生一个稳定账号。退出后再次选择同一角色会回到原账号，因此宠物、地址、订单和服务人员资料保持可见。

## 前端设计

`LoginPanel` 替换为本地角色入口卡片：

- 三个按钮：以宠主身份进入、以服务人员身份进入、以平台管理员身份进入。
- 点击后调用 `createLocalSession(role)`，成功后沿用现有 `getSession()` 刷新状态。
- 首次进入仍走现有安全昵称设置；再次进入复用昵称和业务数据。
- 请求进行中禁用全部角色按钮，防止重复创建会话。
- 页面明确说明这是本机试运营、仅记录线下费用、不收集联系方式。

平台管理员工作区不再渲染 `AdminInvitePanel`。已有组件和 API 可保留但不进入产品界面，以减少本次迁移范围。

## 错误处理

- 非 loopback 或生产环境没有该路由，返回 404/403，且不创建用户或会话。
- 非法角色返回 400，响应不包含内部错误或数据库信息。
- 并发数据库冲突仅重试安全事务或返回统一服务不可用错误，不暴露唯一标记。
- 登录失败继续使用现有中文安全错误映射。

## 测试与验收

- 服务层测试：三个角色可创建会话；同一角色重复进入复用用户；不同角色隔离；并发只产生一个本地用户。
- 路由测试：非生产 loopback 成功，非法角色失败，生产不注册，非 loopback 失败，Cookie 保持 HttpOnly/SameSite。
- UI 测试：无邀请码输入和管理面板；三角色按钮可进入；重复点击受控；页面无联系方式和支付入口。
- 真实 PostgreSQL 浏览器验收：三种角色通过直接入口完成原有闭环；保留隐藏邀请 API 仅用于第二同角色账号的 IDOR 回归。
- 全量执行 lint、typecheck、单元/集成测试、普通构建、pilot 构建、公开 Playwright、pilot Playwright 和真实 PostgreSQL live 验收。

## 本地运行

快速启动文档删除 `pnpm pilot:bootstrap` 步骤。数据库迁移后直接执行 `pnpm pilot:start`，访问本地地址并选择角色。文档仍要求 Node.js 22、PostgreSQL 16、随机数据库密码、字段加密密钥与认证 pepper，且不得把真实密钥写入 Vault 或 `.env`。
