# 真实网站部署设计

## 背景与目标

现有 GitHub Pages 只保存浏览器演示数据。本阶段把已经存在的 Fastify API、React 网站、PostgreSQL 数据模型和 S3 证据存储部署成一个可从公网 HTTPS 访问的真实试点网站。首期闭环是：宠主登录并提交订单，平台后台匹配人员，服务人员提交服务记录，宠主确认完成。继续使用人工收款，不在本阶段接通微信支付。

用户已明确要求继续并授权按最佳判断完成技术准备，不再逐项询问。上线到第三方账户仍必须由用户完成购买、实名或首次授权；任何密码、密钥、Cookie、支付资料都不得保存到仓库或 Obsidian Vault。

## 方案比较

1. **单体应用容器 + 托管 PostgreSQL + S3兼容对象存储（采用）**：保持现有 Fastify 同源托管网站和 API，Caddy 终止 HTTPS。代码改动少，数据库和图片可独立备份，之后微信小程序复用同一 API。
2. **一台服务器同时运行 PostgreSQL/MinIO/应用**：初期费用低，但订单、图片和应用共享单点故障，恢复和容量管理风险较高，不作为真实试点默认方案。
3. **改写为 Serverless/BaaS**：托管运维较轻，但需要重写 Fastify、会话、S3签名和迁移流程，会延迟现有闭环，不采用。

OpenAI Sites 不作为本次生产后端：现有应用依赖长运行 Node 进程、Prisma/PostgreSQL、S3签名和服务端会话。静态 GitHub Pages继续保留为公开演示入口，真实站使用独立 HTTPS 域名。

## 架构

```text
浏览器/后续微信小程序
        │ HTTPS
        ▼
 Caddy（自动证书、基础安全响应头）
        │ 同源 HTTP
        ▼
 React 静态资源 + Fastify API（单一应用容器）
        ├── PostgreSQL（订单、账号、审计）
        └── 私有 S3兼容桶（履约图片/报告证据）
```

应用容器启动前执行 `prisma migrate deploy`，迁移成功后才启动服务。Fastify 的 `/health/ready` 同时检查数据库、加密配置和存储配置，容器及部署验收均以它为准。Caddy 只转发到应用内部端口，公网只开放 80/443。

## 配置与安全

- `NODE_ENV=production`、`PILOT_MODE=enabled`、`PILOT_HOST=0.0.0.0`。
- `PILOT_PUBLIC_ORIGIN` 必须与最终 HTTPS 网站源完全一致，安全 Cookie 才可工作。
- `DATABASE_URL` 使用专用最小权限数据库账号并要求服务商 TLS。
- `FIELD_ENCRYPTION_KEY_V1` 和 `PILOT_AUTH_PEPPER` 是两份不同的随机 Base64 密钥，至少32字节，稳定保管，不可随意轮换。
- S3桶私有，允许网站源的必要 CORS，上传必须携带 SHA-256 checksum；不公开桶或长期读 URL。
- `PILOT_TRUST_PROXY` 只配置实际反向代理容器网段，不信任任意公网代理。
- 微信登录默认关闭；未配置真实 AppID/AppSecret 时网站仍使用既有受控登录方式。普通宠主不使用邀请码，服务人员和管理员由平台审核/创建。
- `.env.production`、证书、数据库备份和对象存储凭据永远不提交。

## 部署单元

- 根目录 `Dockerfile`：固定 Node 22 主版本，多阶段安装/构建网站，运行前数据库迁移，非 root 应用进程，内置健康检查。
- `deploy/compose.production.yml`：Caddy 与应用两个容器；数据库和对象存储为外部托管服务。
- `deploy/Caddyfile`：自动 HTTPS、反向代理和适度安全头；不设置会破坏图片/上传的过度 CSP。
- `deploy/.env.production.example`：只列变量名和安全占位说明，不含可用秘密。
- `deploy/README.md`：从 DNS、外部依赖、生成密钥、部署、验收、备份到回滚的唯一运行手册。
- CI 增加生产镜像构建与容器配置静态验证，但不自动推送或部署到未知账户。

## 数据流与错误处理

用户只访问一个 HTTPS 源，页面和 API 同源，避免生产 CORS 和跨域 Cookie。应用启动时配置、迁移、数据库或 S3缺失即失败关闭，不退化成本地文件或演示账号。上传失败保留订单状态并允许安全重试；数据库迁移失败不启动新版本。回滚只回滚应用镜像，数据库迁移采用向前修复，不自动破坏性回滚。

## 验收

1. Docker 镜像在干净环境构建成功，最终镜像不包含 `.git`、本地 `.env`、备份或运行时证据。
2. Compose 展开通过，应用不直接暴露公网端口，Caddy 仅开放 80/443。
3. 缺少任一生产必需配置时容器失败关闭；完整测试配置时迁移后 `/health/ready` 返回 ready。
4. 现有全仓测试、网站与 pilot 构建通过；生产部署文件有自动化测试覆盖关键安全约束。
5. 真正第三方部署后，使用新建测试账号完成网站登录、下单、后台匹配、服务记录、宠主确认；不使用本机已有真实数据做试验。
6. 完成数据库备份与一次恢复演练，再把站点交给真实用户。

## 明确不包含

本阶段不接微信支付、不开放小程序生产登录、不建立自动通知、不做多区域高可用，也不宣称已完成法律、保险、ICP备案或正式规模运营门槛。真实部署完成表示可以进行受控试点，不等于可无限公开运营。
