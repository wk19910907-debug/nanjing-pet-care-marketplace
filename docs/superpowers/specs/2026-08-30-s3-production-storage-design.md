# S3 兼容生产证据存储设计

## 目标

让 `pnpm --filter @pet/api start:pilot` 在生产试运营配置下能够自行建立标准 S3 兼容签名器，不再要求另一个未提供的宿主程序注入 `S3Signer`。对象存储仍为私有桶，浏览器只获得短期 PUT/GET 签名 URL。

## 方案选择

采用 AWS SDK for JavaScript v3 的 `S3Client`、`PutObjectCommand`、`GetObjectCommand`、`HeadObjectCommand` 和 `getSignedUrl`。这套实现支持 AWS S3 以及提供标准 S3 API 的 R2、MinIO、COS/OSS 兼容端点。保留依赖注入接口供测试和特殊宿主覆盖；只有命令行生产入口自动从已校验配置创建签名器。

不采用生产本地磁盘，因为无法支持多实例、私有访问和持久化安全边界；不绑定单一云厂商专有 SDK，避免阻塞未来迁移。

## 配置

生产模式新增必填 `S3_REGION`，新增可选 `S3_FORCE_PATH_STYLE`（仅接受 `true` 或 `false`，默认 `false`）。已有端点、桶名、Access Key 和 Secret Key 继续由环境变量提供，任何凭据都不得进入日志、错误响应、仓库或 Vault。

## 数据流与安全

上传签名固定桶名、对象键、内容类型、SHA-256 元数据和有效期；内容类型参与签名，SHA-256 元数据被提升到签名查询参数，浏览器无需自行构造额外请求头。下载只签名对象键和有效期。上传完成后服务器执行 `HeadObject`，仅在内容类型、长度和 SHA-256 元数据全部与订单声明一致时接受证据。404 或 `NotFound` 返回“对象不存在”，其他存储错误继续失败，不得伪装成功。

现有浏览器客户端只允许本机相对上传地址，因此需同时允许服务器返回的绝对 HTTPS 签名地址。客户端继续使用 `credentials: omit`，并拒绝 HTTP、用户名密码、URL 片段、非 HTTPS 协议和格式异常的地址；本机相对签名地址保持兼容。

生产服务器从配置创建签名器并注入现有 `createPilotApplication`。测试仍可显式注入假签名器；开发环境继续使用现有受控本地证据目录。

## 验收

- 缺少 `S3_REGION` 的生产配置失败关闭；开发配置不要求它。
- 签名器生成 PUT/GET 短期 URL，并用 HEAD 元数据核验文件。
- 浏览器只接受安全的相对地址或绝对 HTTPS 上传地址，并拒绝不安全变体。
- 生产服务器启动路径会自动注入签名器，且测试覆盖不泄漏密钥。
- API lint、类型检查、全部测试和 pilot 生产构建通过。

## 非目标

本阶段不创建云桶、不购买域名、不申请备案、不提供真实云密钥，也不改变登录、支付、订单或微信小程序业务行为。
