# 网站、小程序与运营后台统一配置设计

日期：2026-08-29  
状态：已获用户确认

## 目标

在现有南京上门喂猫、上门遛狗闭环上增加一套可由运营人员手动维护的统一服务配置，并让网站前端和微信小程序读取同一数据源。运营人员不需要修改代码或重新发布前端，即可调整首批必要运营信息。

本次首批可维护范围固定为：

- 上门喂猫是否开放及起步价；
- 上门遛狗是否开放及起步价；
- 南京开放服务区域；
- 面向用户展示的运营公告；
- 现有服务者审核、人工确认费用和派单操作继续保留。

## 非目标

- 不提供任意编辑订单状态、订单金额或履约记录的通用入口；
- 不在本阶段加入在线支付、退款、优惠券、复杂排班或多城市运营；
- 不把微信 AppID、AppSecret、令牌或其他密钥写入仓库；
- 不以两套独立配置分别维护网站和小程序。

## 方案选择

采用数据库驱动的统一运营目录（Operations Catalog）。目录由 API 服务负责读取、校验和更新，网站、小程序及报价服务均通过共享契约使用它。

未采用以下方案：

1. 仓库内 JSON 配置：修改后需要重启或重新发布，不满足运营人员后台修改的目标。
2. 网站与小程序分别维护：上线速度看似更快，但价格、区域和开关会持续漂移。

## 架构

### 统一运营目录

PostgreSQL 保存一条当前生效的版本化运营目录，至少包含：

- `version`：递增版本，用于并发修改保护；
- `catFeeding.enabled`、`catFeeding.basePriceFen`；
- `dogWalking.enabled`、`dogWalking.basePriceFen`；
- `openDistricts`：受支持的南京行政区代码集合；
- `announcement`：可为空、长度受限的公开公告；
- `updatedAt`、`updatedByUserId`。

金额使用整数分存储和传输。区域使用稳定代码，展示名称由共享契约提供，避免各端自由输入造成不一致。系统迁移时写入一套与当前业务兼容的默认配置，保证升级后可立即使用。

### 共享契约

`@pet/contracts` 定义公开目录、后台更新命令、版本冲突及校验错误。网站、小程序、管理端和 API 共同依赖这些类型与枚举。

公开响应只包含用户端需要的数据，不暴露操作人或内部审计信息。后台响应额外包含版本和更新时间。

### API

新增两组能力：

- 公开读取：任何前端均可获取当前服务开关、起步价、开放区域和公告；
- 管理更新：仅管理员可提交完整配置和预期版本。

更新采用乐观并发控制。若其他管理员已经修改，API 返回版本冲突，管理端刷新后再提交，禁止静默覆盖。

报价与创建订单不接受前端提交的可信价格。服务端读取当前目录，检查服务是否开放、区域是否开放，再生成报价。订单保留成交报价快照，因此后续调价不改变历史订单。

### 管理后台

管理端增加“运营配置”区域，提供：

- 两个服务的启停开关；
- 两个服务的起步价输入；
- 南京服务区域多选；
- 运营公告编辑与预览；
- 保存状态、校验提示、版本冲突提示和最后更新时间。

保存必须一次提交完整且有效的配置。至少保留一个开放区域；价格必须为正数并限制在合理运营区间。现有订单动作仍通过领域命令完成，不增加绕过状态机的数据库编辑器。

每次成功修改写入审计事件，记录管理员、修改时间、修改前版本、修改后版本和变更摘要。

## 网站前端

公开首页与登录后的宠主下单页读取统一目录：

- 仅展示已开放服务；
- 展示服务端返回的当前起步价；
- 区域选择仅包含开放区域；
- 首页展示非空公告；
- 最终报价仍由服务端生成。

目录请求失败时显示“服务配置暂不可用”并禁止提交订单，不用硬编码价格兜底。可以保留最近一次成功数据用于页面展示，但不可据此离线报价或创建订单。

## 微信小程序

小程序不再以本地存储模拟完整业务状态，而是复用统一 API：

- 环境配置提供 API 基础地址，开发、体验和生产环境可切换；
- 首页、服务选择、区域选择和公告消费同一个运营目录；
- 下单、报价、订单详情和进度通过 API 完成；
- 共享契约保证字段和状态与网站一致；
- 页面保持轻量，只保留完成下单所需字段。

认证采用适配器边界。开发环境可使用现有安全的本地试用会话；生产适配器使用 `wx.login` 获取临时代码，由服务端向微信换取身份并建立业务会话。仓库只实现接口和配置读取，不保存微信密钥。正式启用生产登录还需用户在微信公众平台提供 AppID、配置合法 HTTPS 域名及服务端密钥。

在未接入微信支付前，按钮不得宣称“确认并支付”，统一使用“提交订单”或“确认下单”。

## 数据流

1. 管理员登录后台，读取带版本的当前目录。
2. 管理员修改并保存；API 校验权限、版本和字段，事务性更新目录并写审计事件。
3. 网站和小程序重新获取公开目录，更新服务、价格、区域和公告展示。
4. 宠主提交需求；API 以当前目录校验并生成报价。
5. 宠主确认下单；订单保存报价快照，进入现有匹配和履约状态机。

## 错误与安全边界

- 未认证或非管理员调用管理接口返回权限错误；
- 服务关闭、区域关闭或配置失效时，报价和创建订单失败并返回可展示原因；
- 版本冲突返回明确错误，不覆盖较新的配置；
- 公开接口不返回审计字段或内部身份；
- 所有输入由服务端再次校验；前端校验仅改善体验；
- 日志和项目文档不得包含微信密钥、Cookie、令牌或用户隐私数据。

## 验收标准

1. 管理员可在后台修改四类首批运营配置，刷新后数据仍保留。
2. 网站公开页和宠主下单页展示同一配置，关闭服务后无法报价或下单。
3. 微信小程序从相同公开接口读取服务、价格、区域和公告，不依赖重复硬编码。
4. 调价后新报价使用新价格，既有订单金额不变。
5. 两名管理员基于相同旧版本保存时，后提交者收到冲突提示。
6. 每次后台修改都有可追溯审计记录。
7. 管理端不提供任意订单状态编辑能力。
8. 共享检查、单元测试、构建和网站实时端到端流程通过；小程序类型检查与页面/服务测试通过。

## 实施分界

本阶段交付统一目录、后台编辑、网站消费、小程序 API 化所需代码及开发态验证。生产微信登录的代码边界一并完成，但真正连接微信平台取决于外部 AppID、合法域名、HTTPS 和密钥配置；这些外部资料不阻塞网站与小程序开发版验收。
