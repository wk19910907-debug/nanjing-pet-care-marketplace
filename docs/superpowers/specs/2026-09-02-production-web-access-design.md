# 生产网站免登录接单与员工账号设计

## 1. 目标

把现有南京上门喂猫、上门遛狗网站从浏览器本地演示推进为可连接现有 Fastify、PostgreSQL 与 S3 服务的受控真实试点。宠主不需要邀请码、手机号、微信二维码或密码即可提交真实订单；平台管理员和服务人员使用受控员工账号。首期继续人工核对费用，不接在线支付。

本阶段完成以下闭环：

1. 宠主免登录进入预约并创建真实 OWNER 会话；
2. 宠主提交订单并获得可长期保存的高强度恢复凭证；
3. 宠主使用当前浏览器或恢复凭证查看自己的订单、平台消息、服务记录并确认完成；
4. 管理员登录、核对线下费用、匹配服务人员、发送订单消息；
5. 服务人员登录、查看自己的任务、签到、上传证据并提交报告；
6. 所有角色继续使用现有订单权限和状态机，不建立第二套业务闭环。

## 2. 已确认约束

- 仅支持南京的上门喂猫和上门遛狗。
- 宠主只提交需求，由平台匹配服务人员，宠主不能自主选人。
- 宠主入口不使用邀请码、手机号、微信二维码、短信验证码或公开密码注册。
- 管理员和服务人员不开放公开注册，也不通过宠主入口选择角色。
- 不接在线支付、退款自动化、优惠券、保险承诺、地图导航或自动通知。
- 不伪造客服电话、服务人员数量、成交量或保障资质。
- 精确地址、凭证、密码、Cookie、微信密钥和支付资料不得写入日志、仓库或 Obsidian Vault。
- GitHub Pages 继续作为安全体验版；真实试点必须部署网站与 API 同源的独立 HTTPS 地址。

## 3. 方案选择

### 采用：免登录宠主会话 + 恢复凭证 + 员工账号

宠主首次开始预约时，网站在后台创建 OWNER 与 HttpOnly 会话，页面不出现注册步骤。订单创建成功后生成一个 256 位随机恢复凭证，只向宠主显示原文；数据库仅保存域分离 HMAC。当前浏览器依靠会话 Cookie 日常访问，恢复凭证用于更换设备或 Cookie 丢失后的恢复。

管理员与服务人员使用独立员工用户名和密码。首个管理员由服务器命令创建；后续服务人员由管理员后台创建、停用和重置临时密码。服务人员首次登录必须修改临时密码。

该方案不依赖新的外部服务，能复用现有订单、权限、履约、加密和对象存储能力，是当前约束下最短的真实网站闭环。

### 不采用：微信登录优先

微信登录已有小程序 code 交换边界，但网站 OAuth 不是小程序 `wx.login`。它还需要开放平台资质、回调域名、真实 AppID/AppSecret 与外部验收，不能作为本阶段唯一入口。

### 不采用：手机号验证码

手机号找回更符合常见产品习惯，但会引入短信供应商、实名账户、成本、滥用控制和联系方式隐私管理，违反当前“手机号先绕过”的决定。

## 4. 系统边界

### 4.1 复用的现有能力

- `User`、`PilotSession`、`Pet`、`ServiceAddress`、`Order`、派单、履约报告、媒体证据与审计事件；
- 服务端目录、区域开关和报价；
- OWNER、PROVIDER、ADMIN 角色授权；
- 精确地址字段加密与私有 S3 签名上传；
- 同源 Cookie、Origin 防护、生产配置失败关闭和健康检查；
- 管理端人工费用核对与平台匹配流程。

### 4.2 新增的独立边界

1. `PublicOwnerAccessService`：创建免登录 OWNER、签发会话、生成/交换/轮换恢复凭证；不处理订单业务。
2. `StaffCredentialService`：员工密码校验、首次改密、停用与失败限制；不处理角色业务权限。
3. `OrderConversationService`：订单级宠主与平台消息；不替代履约报告或证据。
4. `PublicOwnerEntry`：前端自动建立宠主会话并进入现有预约流程。
5. `StaffLoginPanel` 与 `StaffAccountPanel`：员工登录和管理员账号维护。

## 5. 数据模型

### 5.1 `OwnerRecoveryCredential`

- `id`
- `userId`，唯一关联 OWNER
- `lookupPrefix`，恢复凭证 Base64URL 原文的前 12 字符，只用于把候选范围限制到极小集合
- `tokenHash`，唯一，保存 `HMAC-SHA256(pepper, "owner-recovery-v1\0" + token)`
- `createdAt`
- `rotatedAt`
- `lastUsedAt`
- `revokedAt`

恢复凭证使用加密安全随机数生成 32 字节并编码为 Base64URL。服务端先按 12 字符前缀读取至多 8 个候选，再使用固定时间比较验证完整 HMAC；候选超过上限时失败关闭。除短前缀外原文不入库、不进日志、不放 URL 查询参数。已登录宠主可以轮换凭证；轮换后旧凭证立即失效。

### 5.2 `StaffCredential`

- `id`
- `userId`，唯一关联 ADMIN 或 PROVIDER
- `usernameNormalized`，全局唯一，使用小写 ASCII 登录名
- `passwordHash`，Argon2id 编码结果
- `mustChangePassword`
- `failedAttempts`
- `lockedUntil`
- `passwordChangedAt`
- `disabledAt`
- `createdAt`、`updatedAt`

密码原文永不持久化或记录。管理员不能查看现有密码，只能停用账号或设置一次性临时密码。员工首次登录后必须修改密码才能进入业务工作区。

### 5.3 `OrderMessage`

- `id`
- `orderId`
- `authorUserId`
- `authorRole`，只允许 OWNER 或 ADMIN
- `bodyEncrypted` 与加密版本
- `createdAt`

消息仅支持纯文本，UTF-8 1–500 字，不支持附件、删除、编辑或服务人员参与。服务人员继续通过现有任务状态和履约报告与平台协作。消息内容可能包含运营沟通，按敏感字段加密并进入审计范围。

## 6. 身份与会话流程

### 6.1 宠主首次进入

1. 未登录访客点击“立即预约”。
2. 前端调用 `POST /api/v1/public/owner-sessions`，请求体为空。
3. 服务端创建 OWNER 与 `PilotSession`，设置 Secure、HttpOnly、SameSite=Lax Cookie。
4. 前端读取公开目录后进入现有三阶段预约，不显示注册或身份选择。
5. 若请求失败，停留在首页并显示“暂时无法开始预约”，允许安全重试。

连续重复请求使用浏览器已有 Cookie 返回当前 OWNER，不重复创建用户。服务端对 IP、并发和新用户创建频率设置严格上限，并限制请求体为零长度或空 JSON。

### 6.2 订单成功与恢复凭证

1. 订单仍通过现有鉴权 OWNER 订单接口创建，服务端报价与幂等键保持不变。
2. 第一个订单成功后，若该 OWNER 尚无恢复凭证，前端调用 `POST /api/v1/public/owner-recovery-credentials`。
3. 响应只返回一次原文凭证和一个不含服务器查询参数的恢复链接：`/#/orders/access/<token>`。
4. 页面提供“复制凭证”和“下载恢复文件”，并明确说明丢失后平台当前无法人工找回。
5. 用户关闭提示后仍可在当前有效会话中主动轮换并再次保存。

恢复凭证不保存在 localStorage。日常访问依赖 HttpOnly Cookie；用户自行保存凭证或恢复文件。

### 6.3 新设备恢复

1. 前端从 URL Fragment 读取 token，立即从地址栏清除 Fragment。
2. 前端向 `POST /api/v1/public/owner-recovery-sessions` 提交 token。
3. 服务端使用固定时间比较验证 HMAC、确认关联用户仍为 OWNER、凭证未撤销，并签发新会话 Cookie。
4. 成功后跳转“我的订单”；失败只返回统一错误，不泄露凭证是否曾存在或被撤销。

同一恢复凭证可重复使用，直到宠主主动轮换。它具有账号级访问能力，因此页面必须将其描述为“等同账号密码”，且所有响应使用 `Cache-Control: no-store`、`Referrer-Policy: no-referrer`。

### 6.4 员工登录

- `POST /api/v1/staff/sessions` 接收用户名和密码，成功后签发同一会话机制的 Cookie。
- 失败响应统一，不区分用户名不存在、密码错误、账号停用或临时锁定。
- 失败限制同时按用户名摘要和来源 IP 计算；成功登录清除失败计数。
- `mustChangePassword=true` 时只能访问会话、退出和修改密码接口。
- 管理员与服务人员登录入口位于公开页页脚的“员工登录”，不出现在宠主主操作区。
- 生产环境不渲染“以宠主/服务人员/管理员身份进入”的开发按钮，也不调用 loopback 本地会话接口。

### 6.5 员工账号维护

- 服务器命令通过交互式 stdin 创建首个 ADMIN；命令拒绝从 CLI 参数或环境变量接收密码，避免进入历史和进程列表。
- ADMIN 后台可创建 PROVIDER 登录名和一次性临时密码、停用/启用账号、重置临时密码。
- ADMIN 不能通过网页创建其他 ADMIN，避免浏览器权限扩张；新增管理员仍使用服务器命令。
- 停用账号会撤销其全部活动会话，但不删除用户、履约记录或审计记录。

## 7. 真实订单与消息数据流

1. 宠主会话读取统一服务目录；服务关闭或区域关闭时不能提交。
2. 宠主按“时间 → 宠物 → 上门信息 → 报价确认”填写，备注继续默认收起。
3. 服务端重新验证日期、区域、宠物、地址与报价；创建请求使用现有幂等键，网络重试不得重复下单。
4. 新订单进入现有人工费用状态；页面不得显示“已支付”。
5. ADMIN 核对线下费用并匹配已审核 PROVIDER。
6. PROVIDER 只能读取自己的邀请与任务；地址只在现有状态允许时解密返回。
7. PROVIDER 签到、完成服务清单、上传证据并提交报告。
8. OWNER 查看报告并确认完成。
9. OWNER 与 ADMIN 可在订单详情发送消息。双方通过刷新按钮获取最新消息；本阶段不做 WebSocket、推送或未读通知。

消息列表按 `(orderId, createdAt, id)` 游标分页。OWNER 只能访问自己的订单，ADMIN 可访问平台订单，PROVIDER 不可访问 `OrderMessage`。所有写入产生不包含正文的审计事件。

## 8. 前端体验

### 8.1 公开首页

- 保持现有白色高端商城视觉、两项服务卡片与一个主行动。
- “立即预约”自动建立宠主会话并进入预约，不出现账户表单。
- “我的订单”在有 Cookie 时直接进入；无 Cookie 时显示“使用订单凭证恢复”。
- 页脚提供低权重“员工登录”。

### 8.2 宠主工作区

- 保持当前轻量预约流程，不增加一次性大表单。
- 首单成功页增加恢复凭证保存卡片，凭证默认遮挡，可复制或下载。
- 我的订单展示状态、费用核对说明、平台消息、履约记录和确认按钮。
- 不显示服务人员联系方式、内部账号、其他订单或后台字段。

### 8.3 员工工作区

- 登录页只包含用户名、密码和登录按钮，不显示角色选择、注册、邀请码或找回密码。
- ADMIN 保留现有订单、匹配、服务配置与人员审核界面，并增加员工账号和订单消息入口。
- PROVIDER 保留现有任务与履约界面；首次登录先完成强制改密。

## 9. 错误与恢复

- 创建访客会话失败：不进入表单，保留首页状态并允许重试。
- 订单提交网络响应丢失：复用原幂等键查询结果，不创建重复订单。
- 目录、区域或价格在填写期间变化：服务端拒绝旧报价，前端刷新最新信息并保留可兼容字段。
- 恢复凭证复制/下载失败：原文继续保留在当前页面内存中，直到用户主动关闭或离开；不自动写剪贴板以外的持久存储。
- 恢复失败：统一提示凭证不可用，不显示对应账号、订单数或状态。
- 员工临时密码错误或账号停用：统一提示登录失败；达到限制后短期锁定。
- 消息发送失败：保留未发送文本并允许重试；成功后清空输入框。
- 数据库、加密密钥、S3 或生产配置不可用：应用启动或就绪失败，反向代理不接收新业务流量。

## 10. 安全与隐私

- 恢复 token、会话 token 和密码使用不同的域分离密钥用途；不得互换或复用摘要。
- 凭证和密码相关路由禁止缓存，并设置严格 Origin、内容类型和请求大小校验。
- Cookie 继续使用 Secure、HttpOnly、SameSite=Lax、明确 Path 与到期时间。
- 员工密码最少 12 字，最多 128 字；Argon2id 参数在服务器配置中固定并有性能测试，哈希错误失败关闭。
- 所有恢复、登录、账号停用、密码重置和消息写入均产生脱敏审计事件。
- 精确地址继续使用现有字段加密，平台消息使用相同版本化加密边界但独立用途标签。
- 响应和日志不得包含密码、恢复 token、会话 token、完整地址、消息正文或 S3 凭据。
- 公开访客创建采用 IP/并发/总键数上限；分布式生产部署前必须接共享限流存储，单实例内存限流只允许受控单机试点。
- 恢复凭证无法证明真实身份。本阶段只用于受控试点，不用于争议付款、退款或高风险身份操作。

## 11. API 边界

新增最小路由：

- `POST /api/v1/public/owner-sessions`
- `POST /api/v1/public/owner-recovery-credentials`
- `POST /api/v1/public/owner-recovery-credentials/rotate`
- `POST /api/v1/public/owner-recovery-sessions`
- `POST /api/v1/staff/sessions`
- `PATCH /api/v1/staff/password`
- `GET /api/v1/admin/staff-accounts`
- `POST /api/v1/admin/staff-accounts`
- `PATCH /api/v1/admin/staff-accounts/:userId`
- `POST /api/v1/admin/staff-accounts/:userId/reset-password`
- `GET /api/v1/pilot/orders/:orderId/messages`
- `POST /api/v1/pilot/orders/:orderId/messages`

现有会话查询、退出、目录、预约、管理员、服务人员与履约路由继续使用。所有新增输入使用严格 schema，拒绝额外字段。

## 12. 测试与验收

### 12.1 单元与服务测试

- 256 位 token 生成、域分离 HMAC、固定时间比较、轮换和撤销；
- Argon2id 哈希/验证、首次改密、失败计数、锁定、停用和会话撤销；
- 消息权限、加密、长度、游标与审计脱敏；
- 不记录 token、密码、地址或消息正文。

### 12.2 API 与真实数据库测试

- 重复访客创建复用 Cookie，跨会话恢复只进入同一 OWNER；
- 失效、撤销、伪造和畸形凭证统一失败；
- 公开下单仍由服务端报价并支持幂等重试；
- OWNER 不能读取他人订单或消息，PROVIDER 不能读取消息，ADMIN 只能执行允许的账号操作；
- 停用员工后活动会话立即失效；
- 数据库迁移从现有数据安全升级且不破坏历史订单。

### 12.3 浏览器闭环

在真实应用、临时 PostgreSQL 和对象存储适配器上完成：

1. 新浏览器免登录下单并保存凭证；
2. 另一个浏览器用凭证恢复并看到同一订单；
3. ADMIN 登录、核对费用、发送消息、匹配 PROVIDER；
4. OWNER 读取并回复消息；
5. PROVIDER 首次改密、接收任务、上传证据并提交报告；
6. OWNER 查看报告并确认完成；
7. 未授权浏览器和其他 OWNER 无法读取订单、消息、地址或证据。

### 12.4 发布门槛

- lint、typecheck、全仓测试、数据库测试、普通网站构建、pilot 构建、生产镜像和部署文件测试全部通过；
- 手机、平板、桌面无横向溢出，核心触控目标不小于 44px；
- 生产环境不存在开发三角色入口和本地会话路由；
- 缺失域名、数据库、加密、S3 或员工初始管理员时失败关闭；
- 公网真实部署仍需用户提供主机、域名、备案状态、数据库、S3 和秘密管理；自动化代码完成不等于这些外部条件已完成。

## 13. 非目标与后续

本阶段不实现手机号/微信找回、微信网站 OAuth、微信支付、自动退款、短信/订阅消息、实时聊天、地图定位、自动派单、复杂排班、多城市、多商户、优惠券、服务人员自主获客或开放注册。

后续优先顺序：

1. 使用真实域名和基础设施完成受控试点部署；
2. 真实服务人员审核、协议、隐私政策、客服和应急流程；
3. 微信身份绑定，用于凭证丢失后的可靠找回；
4. 微信支付、退款和通知；
5. 小程序审核和真机验收。
