# 本机生产基础设施预演设计

日期：2026-09-06

## 目标与边界

在当前 Windows 电脑上用 Docker Compose 建立一套可重复启动和验收的生产预演环境，补齐 PostgreSQL、私有 S3兼容对象存储、生产密钥和 WAF。该环境用于验证部署、安全边界、数据持久化和完整业务闭环，不作为公网真实运营环境，也不替代正式域名、Linux 主机、备案或托管 WAF。

成功标准：一条命令可启动整套环境；数据库和对象存储仅在受控网络或本机维护端口可达；应用只能从 WAF入口访问；生产密钥不进入仓库或 Obsidian Vault；迁移、就绪检查、业务闭环、WAF拦截、匿名对象拒绝和重启持久化全部通过。

## 方案选择

采用本机全 Docker 方案：PostgreSQL 16、MinIO、初始化作业、带 Coraza/OWASP Core Rule Set 的 Caddy WAF，以及现有 Fastify/React 应用。暂不使用云数据库、云对象存储或 Cloudflare，因为这些需要外部账号、域名、计费和授权。

## 组件与网络

- `waf`：唯一面向宿主机的应用入口。使用固定版本 Caddy，并通过固定版本 `coraza-caddy` 构建 Coraza 模块；启用 OWASP CRS。WAF清洗客户端转发头，向应用发送单值真实客户端 IP。
- `app`：现有生产镜像。仅加入内部应用网络，不发布宿主机端口；只信任固定 WAF 容器地址。
- `postgres`：PostgreSQL 16，使用持久化数据卷；只加入后端网络。本机维护端口绑定 `127.0.0.1`，不得绑定所有网卡。
- `minio`：S3兼容私有对象存储，使用持久化数据卷；API维护端口仅绑定 `127.0.0.1`。管理控制台默认不发布。
- `minio-init`：一次性、幂等创建私有桶，启用版本控制并设置只允许预演站点源的 CORS；完成后退出。
- `migrate`：使用应用镜像和同一秘密环境执行 `prisma migrate deploy`；完成后应用才可启动。

WAF、应用、数据库、对象存储使用两个隔离 Docker 网络。只有 WAF加入入口网络；应用、PostgreSQL和MinIO加入后端网络。数据库与对象存储不经 WAF 暴露为公开服务。

## 本机名称与 HTTPS

站点使用 `https://petcare.localhost`，对象存储使用 `https://storage.petcare.localhost`。Caddy为 `.localhost` 名称生成本地证书。自动验收使用隔离浏览器上下文并显式信任本次测试证书；不会绕过公网证书警告，也不会把本地证书当成生产证书。

对象上传仍使用 S3预签名 URL。WAF为 `storage.petcare.localhost` 提供 HTTPS并反代到MinIO，使浏览器和应用看到一致的签名主机。该主机只暴露对象 API，不暴露MinIO管理控制台。

## 密钥管理

仓库只包含无秘密模板和生成/启动脚本。实际秘密文件位于 Vault和仓库之外：`%LOCALAPPDATA%\NanjingPetCare\local-production.env`。脚本使用系统密码学随机数生成器创建：

- PostgreSQL应用密码；
- MinIO root 凭据和应用专用访问凭据；
- `PILOT_AUTH_PEPPER`；
- `FIELD_ENCRYPTION_KEY_V1`。

文件创建后通过 Windows ACL 仅允许当前用户和 SYSTEM 读取；脚本不得把值打印到标准输出、日志或测试报告。环境文件路径、值和派生凭据均不得写入Git或Obsidian。若文件已存在，默认复用，不静默覆盖；显式轮换走单独命令并先验证旧密钥仍可解密。

## 数据与请求流程

1. 浏览器访问 WAF 的 HTTPS入口。
2. Coraza/OWASP CRS 检查请求；被判定为攻击的请求返回403并不进入应用。
3. WAF清洗并重建客户端 IP 头，将普通请求转发至Fastify。
4. Fastify通过外部 PostgreSQL连接保存业务数据，通过预签名 S3 URL让浏览器上传证据。
5. `storage.petcare.localhost` 经过同一WAF到MinIO；MinIO桶拒绝匿名列举和读取。
6. 应用就绪检查只有在数据库、对象存储和加密配置均有效时返回成功。

## WAF策略

首次交付启用 OWASP CRS 的保守阻断模式，覆盖常见 SQL注入、路径穿越和脚本注入。为现有 JSON API设置明确请求体大小限制，并对健康检查和静态资源采用最小必要排除。规则版本固定，不在每次启动时下载 `latest`。

WAF层提供按客户端 IP 的共享入口限流，仅用于单个WAF实例的本机预演；应用内登录限流继续保留。预演脚本必须证明两个模拟客户端不会错误共享应用内登录限流。正式多副本生产仍需托管WAF或Redis计数器，不能把本机单实例计数器声明为跨副本能力。

## 启动、失败与恢复

- 启动顺序：PostgreSQL/MinIO健康 → 桶初始化 → 迁移成功 → 应用就绪 → WAF开放入口。
- 任一密钥缺失、数据库不可达、桶不可达、WAF配置无效或迁移失败时，入口保持不可用并返回非成功状态。
- 数据使用命名卷持久化；普通 `down` 不删除数据卷。删除卷必须是单独的显式命令，且不作为自动清理步骤。
- 备份预演包括 `pg_dump` 和MinIO对象版本清单，输出写入仓库/Vault之外的临时受限目录；验收结束后只删除自动创建的非业务临时文件。

## 验收与测试

自动化验收必须覆盖：

1. Compose展开、镜像构建和所有配置语法通过。
2. 无秘密模板可提交，实际环境文件位于仓库/Vault之外且ACL受限。
3. 9项Prisma迁移在新PostgreSQL卷上成功。
4. `/health/ready` 的数据库、对象存储和加密状态均为true。
5. 真实Chrome完成宠主首单、恢复凭据、管理员、服务人员、上传证据、报告和确认完成闭环。
6. SQL注入、路径穿越和XSS探针被WAF拒绝；正常API请求不被误拦截。
7. 匿名访问MinIO桶、对象和管理端点失败；应用签发的限定预签名上传/读取成功。
8. 重启应用、PostgreSQL、MinIO后订单和对象仍存在。
9. 日志、Git差异、进程参数和测试产物不包含生产密钥。
10. 测试结束后临时进程和临时容器清理，但持久化预演卷默认保留。

## 外部迁移

未来迁移到真实运营环境时，保持应用接口不变，将PostgreSQL和S3端点替换为托管服务，WAF替换为有跨实例共享限流的托管入口，并使用有效公网域名与证书。真实上线前仍需完成备份恢复演练、ICP备案/合规、支付商户接入和运营验收。
