# 微信会话接入

## 目标和范围

接通原生客户端已有的 POST `/api/v1/auth/wechat/session`。后台使用微信 code2Session 交换凭证，首次创建 OWNER，再复用现有不透明会话、昵称和业务权限。不增加宠主邀请码，不修改订单表单，不实现支付或小程序发布。

## 选择

- 登录显式开关 `WECHAT_LOGIN_ENABLED=true`，启用时必须提供 AppID、AppSecret 和现有会话配置；关闭返回明确 503，不降级到本地账号。
- 固定微信 HTTPS 接口，禁止跳转，限制等待时间和响应体。错误只映射固定业务码；不返回或记录 code、密钥、openid、unionid、session_key 或请求 URL。
- 复用尚未使用的唯一 `User.wechatOpenId` 字段存放 `wx1:` 加 AppID/openid 的域分离 HMAC，而不是明文标识。不会按昵称、电话或 unionid 合并现有账号；密钥需稳定保管。
- 数据库事务创建/读取身份和会话，首次角色只为 OWNER，既有 OWNER/PROVIDER 角色保留；后台人员拒绝通过这个入口登录。客户端不能提交角色或 openid。
- code 的单次使用由微信交换端强制执行；后台不缓存交换成功结果，不自动重试交换。并发身份创建依靠数据库唯一约束及有限事务重试，不在网络请求期间占用数据库事务。
- 路由只返回 Bearer 令牌与过期时间，无 Set-Cookie。生产跨站保护仅豁免精确原生登录路径的无 Origin、无 Cookie、无 Authorization 请求；其他写接口维持原限制。
- 每 IP 所有登录尝试限流，并限制全局并发与键数量。单进程限流不替代生产网关分布式限流。

## 验证与边界

覆盖真实数据库身份复用、并发、角色隔离、令牌摘要；网关固定参数、超时/异常/超大响应/过期或重复 code；生产路由 Origin、Cookie、输入校验和限流；配置默认关闭和启用校验。运行全部回归及原生构建，独立代码复核。

真实微信凭据未提供，不能声称真机微信登录已验收。网站静态体验版不因此变成共享后台，用户入驻审核、手机号/微信绑定及跨端账号关联不在本次范围。

参考：微信官方 API 类型库 `wechat-miniprogram/api-typings` 的 LoginSuccessCallbackResult 说明 code 五分钟有效且需服务端交换。官方文档站本次访问失败，不将其标为已验证来源。
