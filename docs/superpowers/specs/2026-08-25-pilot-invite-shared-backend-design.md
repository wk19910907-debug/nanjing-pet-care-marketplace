# 南京安心宠邀请制试运营设计

## 目标

把当前只保存在单个浏览器中的公开体验版，升级为可由宠主、平台运营和服务人员在不同浏览器或设备共同操作的受控试运营系统。系统使用现有 Fastify、Prisma 和 PostgreSQL 业务基础，先完成邀请码登录、共享数据、人工费用确认、平台派单、履约报告和宠主确认，不接入公开注册、短信、微信登录或在线支付。

GitHub Pages 继续作为无服务端的公开演示。试运营系统是独立的同源部署入口，默认只向平台邀请的南京试点用户开放。

## 既有约束

- 服务范围仍限定为南京市建邺区、鼓楼区、玄武区和秦淮区。
- 核心服务仍只有上门喂猫和上门遛狗。
- 宠主提交需求，平台负责筛选并匹配已审核服务人员。
- 本阶段不公开手机号、微信二维码或服务人员联系方式。
- 本阶段不接入微信支付；系统只记录平台已在线下核对费用，不在网页内发起、代收或确认金融交易。
- 不收集身份证、证件照片、银行卡或门锁密码。服务人员身份核验和协议签署在线下完成，系统只记录审核状态。
- 真实服务地址属于敏感信息，必须加密存储，并继续遵守候选人员只见模糊区域、被分配人员在服务时间窗内才可查看完整地址的规则。
- Node.js 固定为 22.x，pnpm 固定为 10.x，PostgreSQL 固定为 16.x。
- 所有新行为遵循测试先行；任何公开或试运营发布均需完整验证。

## 方案比较与选择

### 方案 A：邀请码会话 + 同源 Fastify + PostgreSQL（采用）

平台在线下找到首批宠主和服务人员，然后通过运营后台生成一次性邀请码。用户兑换邀请码后获得仅保存在 HttpOnly Cookie 中的服务端会话。Fastify 同时提供 API 和构建后的网页资源，避免跨域 Cookie、CORS 和浏览器存储令牌风险。所有订单与履约状态写入 PostgreSQL，因此多个设备看到同一状态。

该方案不依赖手机号、微信资质或第三方认证服务，能最早形成真实共享数据闭环，并保持后续替换为微信登录的接口边界。

### 方案 B：直接接入微信登录、短信和微信支付

最接近最终消费者产品，但需要备案域名、小程序 AppID、商户号、短信签名、隐私合规和生产密钥。本阶段缺少这些外部条件，无法做成可验证交付，因此不采用。

### 方案 C：公开报名或预约表

实现快，但只产生线索，不能解决跨角色派单、履约和确认，也会提前收集联系方式。它不能满足“正常使用”的目标，因此不采用。

## 交付分层

本规格是一个完整的试运营闭环，但实施按依赖关系拆为三个可独立验证的层：

1. 安全会话与可启动服务：邀请码、会话 Cookie、启动入口、健康检查和同源静态资源。
2. 共享业务读写：角色化列表接口、人工费用确认、平台派单、履约和宠主确认。
3. 试运营网页：登录页、宠主工作区、平台工作区、服务人员工作区和跨浏览器端到端验收。

任何一层失败时不得用浏览器本地数据回退冒充成功；公开演示与试运营模式必须明显区分。

## 运行形态

### 公开演示模式

- 继续由 GitHub Pages 发布。
- 继续使用当前 `DemoApp` 和浏览器本地状态。
- 明确标注不承接真实订单或费用。
- 不出现邀请码输入、真实地址提交或试运营承诺。

### 试运营模式

- `pnpm pilot:start` 启动 Fastify，默认监听 `127.0.0.1`；显式配置 `PILOT_HOST` 后才允许监听局域网或服务器地址。
- Fastify 在 `/api` 提供业务接口，在 `/` 提供试运营网页，在 `/health/live` 和 `/health/ready` 提供不含秘密的健康状态。
- 网页通过构建变量选择 `PilotApp`，不得与 `DemoApp` 共用 localStorage 业务状态。
- 开发环境可使用 PostgreSQL 和本地受控证据目录；生产试运营必须使用字段加密和 S3 兼容对象存储。试运营配置不要求微信支付或微信通知凭据，也不得挂载对应路由；现有完整生产配置仍保持原要求。
- 启动日志只显示监听地址、运行模式和依赖就绪状态，不显示邀请码、会话令牌、地址或密钥。

## 邀请码与会话模型

### 数据模型

新增 `PilotInvite`：

- `id`：UUID。
- `codeHash`：唯一 HMAC-SHA256 摘要，不保存明文邀请码。
- `role`：仅允许 `OWNER`、`PROVIDER` 或 `ADMIN`。
- `targetUserId`：可空。初始化管理员邀请码绑定预先创建的管理员；普通宠主或服务人员邀请码为空，在兑换事务中创建并绑定用户。
- `expiresAt`：默认创建后 24 小时。
- `consumedAt`：成功兑换后写入，邀请码只能使用一次。
- `createdById`：创建邀请码的管理员用户。
- `createdAt`：创建时间。

新增 `PilotSession`：

- `id`：UUID。
- `tokenHash`：唯一 HMAC-SHA256 摘要，不保存明文会话令牌。
- `userId`：绑定唯一用户。
- `expiresAt`：默认登录后 7 天。
- `revokedAt`：退出登录或管理员撤销时写入。
- `createdAt`、`lastSeenAt`：创建和最近使用时间。

邀请码和会话摘要使用独立用途标签与 `PILOT_AUTH_PEPPER` 计算，避免同一明文在不同用途产生相同摘要。`PILOT_AUTH_PEPPER` 必须是至少 32 字节的 Base64 随机值，只通过环境变量注入。

### 初始化与邀请码发放

- `pnpm pilot:bootstrap` 在空数据库中幂等创建一个 `ADMIN` 用户，并生成一个只显示一次的管理员邀请码。
- 原始邀请码只输出到当前终端，不写入仓库、日志文件、Vault 或数据库。
- 已登录管理员可从平台工作区创建宠主或服务人员邀请码。页面只在创建响应中显示一次原始邀请码；刷新后只能看到角色、创建时间、有效期和是否已使用。
- 邀请码默认 24 小时过期，不能续期、恢复或再次查看；需要时创建新邀请码。

### 登录与退出

- `POST /api/v1/pilot/sessions` 接收邀请码，使用统一错误 `邀请码无效或已失效`，避免泄露邀请码是否存在、过期或已使用。
- 成功兑换在同一数据库事务中创建或确认绑定用户、标记邀请码已使用并创建会话；并发兑换只能有一个成功。绑定管理员邀请码不得创建第二个管理员。
- Cookie 名为 `petcare_pilot_session`，设置 `HttpOnly`、`SameSite=Lax`、`Path=/`；生产模式必须同时设置 `Secure`。
- `GET /api/v1/pilot/session` 返回当前用户 ID、角色和会话过期时间，不返回令牌摘要。
- `DELETE /api/v1/pilot/session` 撤销当前会话并清除 Cookie。
- 登录兑换按来源地址限制为每 10 分钟最多 5 次失败；超过限制返回 429，响应不包含邀请码或账户信息。
- 所有改变状态的试运营接口在生产模式校验 `Origin` 与 `PILOT_PUBLIC_ORIGIN` 完全一致。

### 非敏感展示昵称

- `User` 增加可空的 `displayName`，长度为 1–30 个 Unicode 字符。
- 用户首次登录后必须先设置展示昵称，才能进入业务工作区；昵称不是实名，不用于身份核验或登录。
- 昵称禁止包含手机号、微信号、邮箱或连续 6 位以上数字；违反规则返回统一校验错误。
- 运营和订单页面只显示该昵称，不显示登录邀请码、用户 ID、线下身份材料或联系方式。
- `PATCH /api/v1/pilot/me` 只允许当前会话修改自己的展示昵称；角色和审核状态不能通过该接口修改。

## 角色和权限

### 宠主 `OWNER`

- 创建和查看自己的宠物、服务地址和订单。
- 创建报价和订单；不得指定服务人员或提交客户端总价。
- 只查看自己的订单、服务报告和平台可公开的服务人员昵称。
- 服务报告提交后可确认完成或发起争议。
- 无权查看其他宠主、候选服务人员、邀请记录、结算或审计后台。

### 服务人员 `PROVIDER`

- 首次登录后提交服务能力、区域和可服务时间。
- 审核通过前不能收到或接受订单邀请。
- 只查看发给自己的邀请和已分配订单。
- 候选阶段只查看服务区域、服务类型和时间；接受邀请后且位于允许时间窗内，才能读取完整服务地址。
- 只能为分配给自己的订单签到、上传履约证据和提交服务报告。

### 平台管理员 `ADMIN`

- 创建宠主和服务人员邀请码。
- 审核或暂停服务人员。
- 查看待处理订单和符合区域、服务类型、审核状态、可用时间及并发上限的候选人员。
- 启动派单、查看邀请响应和处理失败派单。
- 记录“费用已线下核对”，使订单从 `PENDING_PAYMENT` 进入派单；该动作不调用支付网关，也不声称平台收款。
- 查看脱敏运营数据和审计事件；默认隐藏详细地址和访问说明。

`ADMIN` 继续作为试运营中的合并运营角色。正式运营前再按已有 `REVIEWER`、`DISPATCHER`、`SUPPORT` 权限拆分，不在本阶段增加多角色账户。

## 人工费用确认

- 订单仍由受信任的报价服务计算 `totalFen`，客户端不能提交或覆盖总价。
- 创建订单后状态为 `PENDING_PAYMENT`，页面显示“等待平台核对费用”，不得显示“已支付”。
- `POST /api/v1/pilot/orders/:orderId/manual-fee-confirmation` 仅允许 `ADMIN` 调用。
- 确认动作创建不可重复的内部支付事件，事件提供方固定为 `pilot-manual`，并把订单推进到 `PENDING_DISPATCH`。
- 接口要求 8–100 字符的幂等键；重复请求返回原结果，不产生重复支付事件或审计记录。
- 页面文案为“记录费用已线下核对”，并明确“本系统未处理在线支付”。系统不得收集银行卡、支付码、交易密码或支付凭据。

## 共享业务读模型

现有写接口保留，新增长度受限、按角色过滤的试运营读接口：

- `GET /api/v1/pilot/dashboard`：返回当前角色的计数与待办，不返回其他角色的敏感字段。
- `GET /api/v1/pilot/orders`：宠主只返回自己的订单；服务人员只返回自己的邀请和已分配订单；管理员返回运营所需的脱敏订单。
- `GET /api/v1/pilot/orders/:orderId`：按角色返回允许字段；完整地址继续走既有候选/已分配地址接口，不嵌入通用订单响应。
- `GET /api/v1/pilot/providers/review-queue`：仅管理员，返回申请、服务范围和审核状态，不返回线下身份材料。
- `GET /api/v1/pilot/invites`：仅管理员，返回邀请码元数据，不返回 `codeHash` 或原始邀请码。

所有列表默认按创建时间倒序，首版最多返回 100 项，不提供任意 SQL 排序、自由字段选择或数据导出。

## 平台匹配和履约流程

1. 管理员创建宠主与服务人员邀请码，通过平台控制的线下渠道分别交付。
2. 服务人员兑换邀请码，提交区域、服务类型和可服务时间；管理员完成线下核验后在系统中批准。
3. 宠主兑换邀请码，创建宠物和加密地址，获取受信任报价并提交订单。
4. 管理员核对线下费用记录，订单进入待派单。
5. 管理员启动既有分波派单；只有符合条件的已审核服务人员收到邀请。
6. 服务人员接受邀请，订单原子地绑定该人员；其他并发接受失败。
7. 服务人员在时间窗内签到，完成对应服务清单，提交前后状态和履约证据。
8. 宠主查看报告并确认完成；系统生成既有结算记录，但本阶段不执行线上打款。
9. 每个重要动作写入现有审计表；审计元数据不得包含邀请码、会话令牌、地址明文或证据内容。

## 试运营网页

### 登录页

- 只包含邀请码输入框、登录按钮、隐私和试运营边界说明。
- 不提供注册、找回密码、手机号、微信扫码或第三方 OAuth。
- 登录失败使用统一文案；达到频率限制时显示稍后再试。
- 首次登录成功但尚无展示昵称时，进入单字段昵称设置页；不得要求真实姓名或联系方式。

### 宠主工作区

- 提供宠物、地址、报价和订单的分步表单，避免一次展示全部敏感字段。
- 地址输入明确提示不得填写门锁密码；访问说明字段本阶段不在网页开放。
- 显示订单状态、参考费用、匹配结果和服务报告；确认完成前显示明确确认按钮。

### 平台工作区

- 提供邀请码创建、服务人员审核、人工费用确认、派单和异常状态列表。
- 地址默认只显示南京市、区和服务圈；不提供批量导出。
- 每个危险或不可逆业务动作展示订单或人员标识，并要求单次确认。

### 服务人员工作区

- 提供申请、可用时间、邀请、任务签到和履约报告。
- 不提供任意身份切换；身份由服务器会话唯一确定。
- 完整地址只在后端判定允许时显示，页面隐藏不是权限控制的替代品。

所有页面支持 390×844 手机视口和桌面视口；主要按钮、输入框和选择框触控高度不低于 44px，不出现横向溢出。

## 错误处理和失败关闭

- 数据库不可用时就绪检查失败，登录和业务写操作返回 503，不回退到浏览器本地状态。
- 邀请码无效、过期、已使用统一返回 401；会话过期或撤销返回 401；权限不足返回 403。
- 并发邀请码兑换、人工费用确认、邀请接受和宠主确认依赖数据库唯一约束或事务，冲突返回 409。
- 字段加密失败、证据存储不可用或地址权限判断失败时，相关操作失败关闭。
- 前端保留用户尚未提交的非敏感表单内容；真实地址和报告草稿不写 localStorage。
- 前端错误信息不得显示堆栈、数据库字段、内部路径、Cookie、摘要或配置值。

## 配置和秘密

新增配置：

- `PILOT_MODE=enabled`：显式启用试运营入口；缺省为禁用。
- `PILOT_HOST`、`PILOT_PORT`：监听地址和端口。
- `PILOT_PUBLIC_ORIGIN`：生产 Origin 精确白名单。
- `PILOT_AUTH_PEPPER`：至少 32 字节 Base64 随机值。
- `PILOT_SESSION_DAYS`：默认 7，允许范围 1–30。
- `PILOT_INVITE_HOURS`：默认 24，允许范围 1–168。
- `PILOT_EVIDENCE_DIR`：仅开发/单机试点使用的证据目录，必须位于显式配置路径内。

`NODE_ENV=production` 且 `PILOT_MODE=enabled` 时，配置必须要求数据库、字段加密、试运营 Origin、认证 pepper 和 S3 兼容对象存储；不得要求微信支付或微信通知配置。`PILOT_MODE` 未启用时，现有完整生产配置校验保持不变。

任何真实值不得写入 `.env.example`、README、测试快照、Vault 或 Git 历史；示例只写生成方法和占位说明。

## 测试与验收

### 单元与集成测试

- 邀请码只存摘要、单次兑换、过期、并发兑换和角色白名单。
- 会话创建、Cookie 标志、过期、撤销、退出和无效会话。
- 登录失败频率限制和统一错误文案。
- Origin 校验、生产配置缺失失败关闭和健康检查无秘密。
- 宠主、服务人员、管理员三种角色的列表与详情字段隔离。
- 人工费用确认只允许管理员、总价不可篡改、幂等且不调用真实支付网关。
- 候选与分配地址权限、履约归属、并发接受、审计脱敏和重启后持久化。

### 浏览器验收

使用至少三个隔离浏览器上下文和同一个真实测试数据库：

1. 管理员登录并创建宠主、服务人员邀请码。
2. 服务人员兑换邀请码、提交申请和可用时间；管理员批准。
3. 宠主兑换邀请码，创建宠物、加密地址、报价并下单。
4. 管理员记录费用已线下核对并启动派单。
5. 服务人员只看到自己的邀请，接受后在允许时间窗读取地址、签到并提交完整履约报告。
6. 宠主只看到自己的订单，查看报告并确认完成。
7. 刷新三个浏览器并重启 API，角色会话和共享订单状态仍正确；已撤销会话失效。
8. 验证另一宠主、另一服务人员、过期邀请码和跨角色接口均不能读取或修改目标订单。
9. 验证手机和桌面布局、44px 控件、无横向溢出及无浏览器控制台错误。

- 独立代码复审无 Critical 或 Important 问题；任何 Minor 必须记录处理决定。

## 明确不在本阶段实现

- 公开注册、手机号验证码、微信登录、微信公众号或小程序发布。
- 微信支付、银行卡收款、自动退款、真实结算打款或发票。
- 地图 SDK、实时定位、自动导航或后台轨迹采集。
- 在线收集身份证、证件照片、背景调查材料、合同或银行卡。
- 站内聊天、公开联系方式、自动短信、微信模板消息或客服工单。
- 多城市、多币种、会员、优惠券、订阅、评价排行或动态定价。
- Kubernetes、多区域高可用或自动扩缩容。

这些能力需要单独的资质、隐私、支付和运维设计，不得在本阶段用假接口或误导性文案冒充完成。
