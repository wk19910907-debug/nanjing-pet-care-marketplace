# 公开落地页与信任转化层设计

## 目标

在不公开微信二维码、手机号或其他联系方式的前提下，把现有“南京安心宠”公开体验页从单一操作界面补全为访客能够快速理解的产品落地页。访客应在手机端首先看懂服务范围、参考价格、平台价值和安全边界，并能一键进入现有宠主下单体验。

## 产品边界

- 公开页面仍是安全演示版，不承接真实订单。
- 不增加微信二维码、手机号、报名表、聊天入口或虚假的客服按钮。
- 不采集、上传或分析访问者数据；现有订单状态继续只保存在浏览器 `localStorage`。
- 不改变平台运营与服务人员的既有演示闭环。
- 不改变本地启动地址、GitHub Pages 地址或微信小程序代码。

## 页面信息架构

页面按以下顺序组织：

1. 品牌顶栏与安全体验标识。
2. 首屏价值主张、平台服务闭环和“立即体验下单”主按钮。
3. 服务与价格：上门喂猫参考价 ¥32/次、上门遛狗参考价 ¥37/次，覆盖建邺区、鼓楼区、玄武区和秦淮区体验选项。
4. 平台保障：人员审核、平台匹配、履约报告、异常处理四项说明。
5. 三角色体验导航和现有订单操作区。
6. 常见问题：是否是真实订单、数据保存位置、支持区域和后续正式运营边界。
7. 页脚安全提醒。

## 组件设计

新增 `apps/admin/src/demo/PublicLanding.tsx`，只负责静态产品信息与转化按钮，不读取或修改订单状态。它接收 `onStartOrder(): void`，由 `DemoApp` 负责切换为宠主身份并滚动到带有 `id="order-experience"` 的体验导航区域。

`DemoApp` 保留现有状态机和三角色工作区，新增转化回调与 `PublicLanding` 组合，不把静态营销内容继续塞进已有状态管理逻辑。

`apps/admin/src/styles.css` 增加价格卡片、保障卡片、FAQ、主按钮和手机端布局。所有新交互元素保持至少 44px 可点击高度；390px 宽度下不得产生横向滚动。

## 文案与真实性

- 价格明确标注为“体验参考价”，不得描述为已经开放接单的正式报价。
- 服务范围明确标注为“体验区域”，不得暗示已经在南京全市运营。
- 保障内容描述产品流程能力，不声称已完成线下人员审核或保险接入。
- 主按钮使用“立即体验下单”，不使用“立即预约”“立即支付”或“联系客服”。
- FAQ 明确说明当前订单不会发送到服务人员，也不会产生费用。

## 搜索与分享元信息

修改 `apps/admin/index.html`：

- 页面标题为“南京安心宠｜上门喂猫与遛狗平台体验”。
- 添加中文搜索描述，包含南京、上门喂猫、遛狗、平台匹配和安全体验版。
- 添加 canonical URL 指向 GitHub Pages 固定地址。
- 添加 Open Graph 的 `og:type`、`og:title`、`og:description` 和 `og:url`。
- 不添加不存在的分享图片，不引入第三方统计脚本。

## 交互流程

访客点击“立即体验下单”后：

1. 当前身份切换为“宠主”。
2. 页面平滑滚动到三角色体验导航与宠主表单。
3. 现有下单、匹配、履约、报告和确认流程保持不变。
4. 页面刷新后仍由现有本地存储恢复订单。

## 错误与降级

- 浏览器不支持平滑滚动时，仍通过元素 `scrollIntoView` 到达目标区域。
- JavaScript 尚未加载时，静态标题和描述仍由 HTML 元信息提供。
- 没有联系方式时不显示空白联系卡片或不可用按钮。
- 如果访客误把体验当成真实服务，首屏、价格区、FAQ 和页脚均提供一致的演示边界说明。

## 验证标准

- 新 Playwright 测试先证明当前页面缺少价格、保障、FAQ、元信息和转化按钮，再在实现后通过。
- 桌面端能看到价值主张、两项服务价格、四项平台保障和 FAQ。
- 点击“立即体验下单”后，“宠主”处于选中状态且宠主表单可见。
- 页面标题、搜索描述、canonical 和 Open Graph 元信息正确。
- 390×844 视口无横向溢出，按钮和正文可操作、可阅读。
- 原有 102 个 Vitest 测试、类型检查、生产构建和两条核心 Playwright 流程继续通过。
- GitHub Pages 部署后在线页面返回 HTTP 200，新增文案可见，完整服务闭环仍可完成。

## 非目标

- 不增加真实联系方式或客户线索收集。
- 不接入真实支付、数据库、短信、地图、微信登录或服务者审核。
- 不购买自定义域名，不调整备案或法律文件。
- 不修改当前参考价格的计价规则。
