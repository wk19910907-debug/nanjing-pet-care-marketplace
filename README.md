# 南京安心宠

面向南京本地的“上门喂猫 + 遛狗”预约平台。宠主只需提交需求，平台统一匹配通过资料审核的服务人员，并跟踪上门履约与宠主确认。

当前交付包含网站、小程序源码和本地运营后台。网站与小程序读取同一份运营配置；本地试运营入口连接真实 PostgreSQL 和同源 API，可由宠主、平台运营、服务人员共同完成共享订单闭环。

## 在线体验

无需安装，直接打开：

<https://wk19910907-debug.github.io/nanjing-pet-care-marketplace/>

在线页面是安全体验版：订单数据只保存在当前浏览器，不会提交到服务器。请勿填写真实手机号、精确住址、门锁密码、支付信息或其他敏感信息。

公开页同时展示两项服务的体验参考价、南京体验区域、平台匹配与履约保障说明、常见问题，以及进入宠主下单体验的快捷入口。页面不提供联系方式，也不承接真实订单。

- 访客可选择服务和体验区域，查看不具约束力的体验参考价，并将这两项选择带入浏览器本地保存的体验下单表单。
- 服务人员可提交仅含体验昵称、服务区域、服务项目和经验说明的申请；平台审核通过后，才会进入符合区域与服务类型的订单匹配池。该流程完全保存在当前浏览器，且不接受真实联系方式、身份证明或其他身份文件。
- 平台匹配后，服务人员体验页会切换到被匹配的已认证人员；也可在已认证体验身份间切换。每个身份只能开始和提交属于自己的订单，刷新后会优先恢复有进行中任务的人员。

## 立即查看公开网页

Windows 用户直接双击根目录的 `start-local.cmd`，等待终端显示启动成功，然后在 Chrome 打开：

<http://127.0.0.1:43123>

也可以在 Node.js 22 和 pnpm 10 环境中执行：

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

公开网页中的演示操作顺序：

1. 在公开页选择服务和体验区域后，可点击“按此方案体验下单”带入表单；也可直接选择“宠主”，填写宠物、区域、地址和时间，点击“提交订单”。
2. 选择“平台运营”，为订单选择已认证人员，点击“确认匹配”。
3. 选择“服务人员”，点击“开始服务”。
4. 完成两项履约清单、填写服务记录，点击“提交服务报告”。
5. 回到“宠主”，查看报告并点击“确认完成”。

刷新页面不会丢失订单。需要重新演示时点击“恢复体验数据”。

## 使用微信小程序端

1. 安装并打开微信开发者工具。
2. 选择“导入项目”。
3. 项目目录选择本仓库的 `apps/miniprogram`。
4. 本地界面预览可使用游客 AppID；真实登录与下单必须换成已登记的小程序 AppID。
5. 在小程序扩展配置中提供 `developmentApiBaseUrl`（开发工具本机地址）或 `apiBaseUrl`（体验版/正式版 HTTPS 合法域名）。
6. 首页会读取后台启用的服务、实时起步价、开放区域和运营公告；预约页登录后读取宠物与地址，取得服务器报价后才允许提交订单。

开发版通过仅限回环地址的本机宠主会话验收下单，不需要微信密钥。源码不包含 AppSecret、令牌或生产域名。正式发布前必须配置真实 AppID、微信后台合法 HTTPS request 域名，以及服务端微信 code 换取会话的密钥；缺少这些外部条件时不能宣称微信登录已上线。

## 使用真实本地预约闭环

正式界面的本地试运营入口使用 PostgreSQL 保存共享订单，不依赖邀请码。按 [`docs/operations/pilot-quickstart.md`](docs/operations/pilot-quickstart.md) 配置一次性本地环境并执行 `pnpm pilot:start`，默认打开：

<http://127.0.0.1:3000>

宠主验收路径：

1. 在首页选择“立即预约”，首次访问会创建匿名宠主会话、下载恢复凭据，再设置展示昵称。
2. 首页选择“上门喂猫”或“上门遛狗”。
3. 第一步选择服务、时间与时长；第二步选择或添加宠物和地址；第三步查看服务器报价并提交订单。
4. 平台核对费用并匹配服务人员后，宠主可在首页与“我的订单”查看真实状态。
5. 服务人员完成签到、履约图片和报告后，宠主查看记录并确认完成。

平台管理员可在“运营配置”中统一开关两项服务、修改新订单起步价、选择南京开放区域并发布短公告。保存立即影响官网、小程序和后续服务器报价；已创建订单金额保持不变。若需回滚，重新保存上一版业务值即可，历史订单无需修改。

## 当前交付边界

公开网页是浏览器本地演示，不承接真实订单。本地试运营入口是可操作的共享数据闭环，但仍只适合单机验收，不能直接暴露到局域网或公网。为了安全，请勿填写门锁密码。

当前未接入在线支付，也未公开展示手机号、微信二维码、邀请码或邀请入口。费用状态由平台线下核对；服务范围和接单时间以平台确认结果为准。

正式对外运营前仍需完成：手机号验证、微信支付商户接入、文件存储、地图定位、生产数据库、域名与备案、微信小程序审核、隐私政策和服务人员真实审核流程。

## 本地试运营

仓库同时包含独立的本地试运营入口。它使用同源 Fastify、PostgreSQL 和仅存于 HttpOnly Cookie 的服务器会话，让宠主、平台运营和服务人员在不同浏览器共同完成真实共享数据闭环。宠主从“立即预约”创建会话并保存恢复凭据；员工使用管理员线下创建和交付的账户登录。页面不提供公开注册、手机号、微信二维码、邀请码、邀请管理、在线支付或联系方式。界面采用暖珊瑚色“可信服务型”风格，宠主预约压缩为三个清晰阶段。

单机试点启动、管理员交互式引导和安全清理步骤见 [`docs/operations/pilot-quickstart.md`](docs/operations/pilot-quickstart.md)。它需要 Node.js 22、pnpm 10 和 PostgreSQL 16。不要把公开 GitHub Pages 体验版与试运营入口混用：它仅保存浏览器本地演示数据，绝不是生产订单或同源 API Origin。

## 开发验证

不需要预先准备数据库的真实试运营闭环验收：

```powershell
pnpm test:e2e:live
```

该命令会自行创建、迁移并清理 PostgreSQL 16、API 进程和证据目录。普通静态检查、构建与公开演示浏览器测试可在 clean shell 中直接运行：

```powershell
pnpm lint
pnpm typecheck
pnpm build
pnpm --filter @pet/admin test:e2e
```

正式界面交付验收使用：

```powershell
pnpm check
pnpm pilot:build
pnpm test:e2e:live
```

`pnpm test` 和聚合命令 `pnpm check` 包含 API 集成测试，要求 `DATABASE_URL` 指向已执行全部 Prisma 迁移的 PostgreSQL。可按 [`docs/operations/pilot-quickstart.md`](docs/operations/pilot-quickstart.md) 的容器、就绪等待和迁移步骤准备一次性数据库；不要在 clean shell 中裸跑后误判结果。

验收范围、隔离边界和故障处理见 [`docs/testing/pilot-live-acceptance.md`](docs/testing/pilot-live-acceptance.md)。

详细的基础设施说明见 `docs/operations/LOCAL.md`。
